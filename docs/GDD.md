## 1-3. 핵심 메카닉

### 조작
| 행동 | 입력 |
|---|---|
| 셈지기 소환 | 좌측 덱 카드 **탭** (셈력 충분 + 쿨다운 해제 시) |
| 문제 응답 | 하단 **숫자패드 0~9** → 자릿수가 차면 **자동 제출** |
| 지우기 | ⌫ (자릿수 가변 유형은 확인 버튼 노출) |
| 일시정지 | 우상단 |

> **주 입력이 숫자패드인 이유는 취향이 아니라 실측이다.** 4지선다의 무작위 정답률 25%로
> 시뮬레이션을 돌리면 **ST1~5와 ST8을 그냥 통과**한다(§1-4 G6). 4지선다를 주 입력으로 쓰면
> 게임이 "찍기로 굴러가는 상태"가 되어 학습이 사라진다. 4지선다는 저학년·읽기 부담 유형에만 보조로 쓴다.

### 전투 규칙
- 좌 아군 성(x=0) ↔ 우 적 성(x=1000). 소환된 유닛은 **자동 전진 → 사거리 내 적을 만나면 정지·공격**.
- **승리** = 적 성 HP 0 / **패배** = 아군 성 HP 0 / 420초 초과 = 무승부(교착 방지)
- 동시 출전 상한 **60기**.
- 🔎 **시뮬레이션 추상화(중요)**: 밸런스 프로브는 앞줄 유닛들이 **겹쳐 서서 함께 때리는 '클러스터' 모델**로
  전투를 근사한다. 이 장르(냥코류)의 실제 거동에 가깝고, 엄격한 1열 차단 모델로 바꿔 실험해 보니
  **한 번에 1기만 교전해 물량 자체가 무의미해졌다**(실측). 다만 이 근사는
  "빠른 적이 아군 무리를 지나쳐 성을 때리는" 누수를 완전히 막지 못한다.
  → **Phase 4 headless 검수에서 실제 엔진의 전선 거동(추월 금지·원거리 후방 배치)을 별도로 검증한다**(DoD 4).

### 셈력(자원)
| 공급원 | 값 |
|---|---|
| 시작 소지금 | **200** (초반 연속 오답이 회복 불가 나선이 되지 않게 하는 완충 — 실측으로 추가) |
| 연타 방지 | 응답 **0.25초 미만**은 콤보 미적립(보상은 지급). 유창성 게임에서 '빠름'을 벌하면 안 된다 |
| 자동 충전(바닥선) | **5.8/초**(ST1) → **7.4/초**(ST9+). 스테이지당 +0.2, 상한 +1.6 |
| **문제 정답** | **+46 × 콤보배율** (주 공급원) |
| 콤보 배율 | 직전 연속 정답 0~2회 ×1.0 / 3~4회 ×1.2 / 5~7회 ×1.4 / **8회 이상 ×1.6** |
| 오답 | 콤보 0 리셋 + 힌트 1회 노출. **성 HP 피해 없음** |

> 🔴 **바닥선을 스테이지와 함께 크게 키우면 안 된다.** 첫 시안은 7→12/초로 키웠는데,
> 그 결과 후반에도 "찍기"가 통과했다(실측). 성장은 **학습 보상 쪽에만** 둔다.

### DDA (적응형 난이도)
| 항목 | 값 |
|---|---|
| 발동 | **연속 오답 2회**마다 1단계 하향 (최대 3단계) |
| 효과 | 출제 난이도 하향 → 체감 정답률 **+10%p/단계** |
| 대가 | **보상 −30%/단계** (쉬운 문제로 자원 파밍하는 경로 차단) |
| 회복 | 연속 정답 3회마다 1단계 원복 |

> DDA는 GDD 본문·프로브·DoD에 **모두** 정의돼 있어야 한다(v1.0에서는 리스크 대응책으로만 언급하고
> 스펙도 구현도 없이 "프로브로 재검증"이라고 적혀 있었다 — 허위 검증 선언이었고 교차검증에서 지적됐다).

| **아군 성장('셈나라 기운')** | `1.13^(ST−1)` — 🔴 **진도 연동 자동 적용**(먹물로 구매하지 않는다) |

> 약 **23,818 먹물**이 필요한데 ST10까지 획득 가능한 총량은 **540**이었다. 도달 불가능한 성장을
> 전제로 밸런스를 낸 셈이었다. 이제 성장은 **진도에 따라 자동**이고, 먹물은 셈지기 해금·꾸미기에만 쓴다.
> (부수 효과: 아동에게 학습 외 그라인딩을 강요하지 않게 된다.)

- 프로브의 정답률은 독립 베르누이 시행이다. 문항 난이도·힌트·재도전·0.4초 하한은 모델에 없다.
  응답 시간만 숙련도와 연동돼 있다(정답95% 2.4초 ~ 정답0% 4.7초).

### B. 문항 생성기 (교재 복제 없음)

```ts
// src/edu/generator.ts — 순수 함수, 시드 결정론
generate(type: QType, level: 1|2|3|4|5, rng: Rng): Question
// → { id, type, level, prompt: "8 × 7", answer: 56, digits: 2, difficulty: b }
```

- 모든 문항은 **파라미터 조합으로 생성**한다. 문제은행 파일도, 교재 전사도 없다.
  → 교재·문제집 저작권 리스크를 **현저히 낮춘다**(0으로 만든다고 단정하지는 않는다 —
  생성 규칙 자체가 특정 교재 구성을 그대로 옮긴 것이면 여전히 다툼의 여지가 있다).
- 레벨별 조합 수가 40 미만인 유형은 **최근 12문항 재출제 금지 큐**를 둔다.

**오답 후보(4지선다 보조 사용 시) — 오개념 기반**

| 오개념 | 규칙 | 예(8×7=56) |
|---|---|---|
| 인접단 혼동 | `a×(b±1)`, `(a±1)×b` | 48, 64, 49, 63 |
| 연산자 혼동 | `a+b` | 15 |
| 자리올림 누락 | 십의 자리 −10 | 46 |
| 자릿수 반전 | 십·일의 자리 교환 | 65 |

> 🔴 **필수 테스트 3종** (`tests/quiz-distractor.spec.ts`)
> ① **정답의 크기 순위 분포 균등**(카이제곱) — ±1·±2 대칭 오답은 정답이 늘 가운데 값이 되어
>    계산 없이 최대·최소만 버려도 정답률 45%가 나온다(과거 실측).
> ② **화면 위치 분포 균등** — 정답이 특정 슬롯에 몰리지 않는지.
> ③ **보기 중복·자릿수 단서 없음** — 정답만 자릿수가 다르면 계산 없이 풀린다.

### C. 숙련도 추정 (Elo)

```
P(정답) = 1 / (1 + 10^((b − θ) / 400))
정답: θ += K(1 − P)   오답: θ −= K·P     K = 32(첫 20문항) → 16
θ·b 는 유형별로 따로 관리한다 (M2 능력과 D1 능력은 다르다)
```

**척도·초기값 정의(v1.0에 없어 지적된 부분)**
- **b 척도**: 유형×레벨 조합마다 고정 난이도를 부여한다. 기준점 `A1 level1 = 1000`,
  같은 유형 내 레벨 1단계 = **+60**, 유형 간 간격은 선수 그래프 깊이 × **+80**.
- **θ 초기값**: 가입 진단검사(20문항, 유형 6종 교차) 결과로 유형별 초기 θ를 부여. 미측정 유형은
  선수 유형 θ − 80.
- **b 재보정**: 누적 응답 500건마다 유형×레벨별 실제 정답률로 b를 재추정하고,
  **재보정 전후의 예측 정확도(Brier score)를 로그로 남긴다.** 개선이 없으면 롤백.
- **수렴 한계 명시**: 20문항으로는 θ의 신뢰구간이 넓다. **초기 20문항 구간에서는 출제를
  "선수 유형 확인" 위주로 하고, 성과 리포트에는 50문항 이상 누적 후에만 θ를 노출한다.**

**출제 목표 난이도**
- **L1(전투 중)**: `P(정답) ≈ 0.85` — 유창성.  **L2(관문)**: `P(정답) ≈ 0.60` — 도전.
- 🔎 "학습 최적 정답률 ≈ 85%"는 문헌에서 제시된 주장이며 본 대상·과제에 그대로 적용되는지는
  **파일럿 A/B(0.75 / 0.85)로 확정**한다.

**⚠️ 평가 순환논리 방지**: 숙련도 갱신은 **prequential**(예측 → 채점 → 갱신) 순서 고정.
단 prequential은 "같은 응답 누출"만 막는다. **힌트·재도전으로 오염된 응답은 θ 갱신에서 제외**하고,
적응 출제로 인한 선택 편향은 위 b 재보정 로그로 감시한다.

### D. SRS(간격 반복) — **벽시계 기준**

| 상태 | 다음 출제 | 승급 조건 |
|---|---|---|
| 신규 | 즉시 | — |
| 학습중 | **1일 후** | 연속 2회 정답 |
| 익힘 | **3일 후** | 연속 2회 정답 |
| 다짐 | **7일 후** | 연속 2회 정답 |
| 완성 | **21일 후** | — (오답 시 '학습중'으로 강등) |

> 🔴 v1.0은 간격을 "판 수"(1→3→7→14판)로 정의했는데, **한 세션에 다 소진할 수 있어
> 장기 파지를 전혀 측정하지 못한다**(교차검증 지적). 벽시계 기준으로 교체했다.
> 같은 날 재접속 시에는 **미도래 항목을 L1 큐에 넣지 않는다**(대신 신규·오답 항목으로 채운다).

> 🔴 **구현 함정 2건(과거 실측)**
> ① 출제 큐에서 항목을 **`splice`로 빼면 채점 때 못 찾아 승급 로직이 죽는다** — 문서엔 3→7→15인데
>    실제는 3→3→3. 큐에서 빼지 말고 **상태 필드만 갱신**하고 승급을 **실행으로 재현 검증**한다.
> ② 오답노트 시드를 `slice(0,N)` 고정으로 잡으면 오래된 항목이 **영구 미출제**(tail starvation).
>    **라운드로빈 티켓 필드**(`lastServedAt`)로 막는다.

### E. 시간 제한
- **L1 문항엔 제한 시간이 없다**(전투가 이미 압박이다). 늦으면 자원이 안 차서 자연히 불리해질 뿐.
- **L2 관문은 문항당 15초 + 읽기 보정**: `제한 = 기본 + 프롬프트 글자 수 × 0.12초`.
  (유형별 상수만 쓰면 같은 유형 안 43자 vs 66자 편차를 못 잡아, "몰라서"가 아니라 "못 읽어서"
  시간 초과가 난다 — 그건 학습 신호가 아니다.)

### F. 학년 적합성 게이트 (기계 검증 · **2단**)

1. **용어 게이트** — 학년별 **금지 용어 목록**(2학년 금지: 배수·약수·통분·자연수·소수(小數)·분모 …)과
   전 UI 문자열·문항 프롬프트·해설을 대조, 위반 시 테스트 실패.
2. **유형 게이트(신설)** — 각 문항 유형의 **대상 학년대가 프로필 학년 범위를 넘지 않는지** 검사.
   활동이 쉬워 보여도 교육과정 진도를 앞당기면 위반이다(`MX1` 사례).
3. **라벨-메커닉 일치** — "곱셈구구"라 써 놓고 판정이 단순 덧셈이면 개념을 안 가르치는 것이다.

### G. 학습 성과 측정 (상업적 근거)

| 지표 | 정의 | 목표 | **필요 원시 데이터** |

| 유형별 θ 변화 | 주간 Elo 상승폭 | 4주 +80 | `thetaWeekly[]` 스냅샷 |

```jsonc
// localStorage key: "gugu:save"
{
  "version": 1,
  "data": {
    "profile": { "nickname": "자동생성", "gradeBand": "2-4", "createdAt": "2026-07-28" },
    "progress": { "chapter": 1, "cleared": { "1": 3, "2": 2 }, "challengeCleared": [] },
    "deck": ["kkachi", "musoe", "bungbung", "dokkabi", "haetae"],

    "currency": { "meokmul": 240, "recovered": 12 },
    "edu": {
      "theta":  { "M1": 1180, "M2": 940 },
      "thetaWeekly": [ { "week": "2026-W30", "M1": 1120, "M2": 900 } ],   // 4주 변화 판정용
      "stats":  { "M2": { "attempts": 240, "correct": 191, "correctFast": 154,
                          "answerMs": 612000 } },                          // 자동화율·문항밀도
      "playMs": 1840000,                                                   // 문항 밀도 분모
      "diagnostics": [ { "date": "2026-07-28", "score": 13, "of": 20 } ],  // 사전·사후
      "srs": { "M2:8x7": { "state": "익힘", "streak": 1,                    // 🔴 연속정답 카운터
                           "dueAt": "2026-08-02", "lastServedAt": "2026-07-30" } },
      "retentionLog": [ { "key": "M2:8x7", "matured": "2026-07-10", "recheck": "2026-07-31", "ok": true } ],
      "ddaLevel": 0
    }

```

- 🔴 `srs.streak` 없이 "연속 2회 정답" 승급을 설계하면, 1회 맞히고 앱을 끄는 순간
  진행이 조용히 리셋된다(누적형 목표를 boolean으로 설계하는 전형적 공백).
- 🔴 **손상 세이브 방어를 try/catch에 기대지 말 것** — `Object.values(123)`은 예외 없이 빈 배열을
  돌려준다. 경계에서 **필드별 타입 검사 → 모르는 키 제거 → 기본값 복구**(화이트리스트 정규화).
- 🔴 **파생 카운터를 기록에서 재계산할 땐 기록이 없는 경우까지 덮어야 한다** — `for (기록)` 루프만
  돌면 기록이 아예 없는 항목의 조작값이 살아남는다. **전체 0 초기화 후 기록으로 채운다.**
- 🔴 **날짜 문자열에 `toISOString().slice(0,10)` 금지** — UTC 변환이라 KST에서 하루 밀린다.
  SRS `dueAt` 전체가 하루 어긋난다. 로컬 `getFullYear/getMonth/getDate` 포맷터로 통일하고
  `addDays(x,0)===x` 회귀 테스트를 건다.

## 부록 B. Phaser를 쓰지 않은 이유 (v1.2 구현 결정)

v1.0 기획서는 Phaser 3.90을 지정했다. 실제 구현에서는 **바닐라 TS + Canvas 2D + DOM UI**로 바꿨다.

| 근거 | 내용 |
|---|---|
| 이 게임의 렌더는 단순하다 | 전장은 가로 한 줄 위의 스프라이트 나열이다. `drawImage` 루프면 충분하고 씬 그래프가 필요 없다 |
| **학습 UI는 DOM이 압도적으로 유리** | 숫자패드·문제 카드·리포트 표는 접근성(포커스·스크린리더)·한글 폰트·터치 타깃이 DOM에서 공짜로 해결된다 |
| 번들 | Phaser만 ~1.1MB. 현재 전체 번들은 **JS 48KB**다. 학교 와이파이·저사양 크롬북에서 체감 차이가 크다 |
| 알려진 함정 회피 | 컨테이너 히트영역 좌표계·씬 인스턴스 재사용·블렌드 모드 등 과거에 반복해서 물렸던 문제군이 통째로 사라진다 |

대신 포기한 것: 파티클·트윈·물리 엔진. 현재 연출(히트스톱·틴트·셰이크·bob)은 직접 구현했고,
이보다 복잡한 연출이 필요해지면 그때 라이브러리를 검토한다.
