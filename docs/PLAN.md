### 1-4. 서버 권위·재화 안전망

- 🔴 **구독 상태를 클라이언트가 쓸 수 있는 문서에 두지 않는다.** 권한 판정 필드가 사용자 write 허용
  문서에 있으면 자기 승격이 가능하다 → **Functions 전용 write** 또는 **Auth custom claim**.
- 🔴 **Admin SDK 경유 쓰기는 Security Rules가 막지 못한다.** 생성류 액션(리포트 생성·동기화)에
  **일일 캡 + 멱등 키**를 함수 내부에 둔다.
- 🔴 **재화·결제 4단계 안전망**(클라우드 동기화를 켜는 순간 적용):
  ① **감사 로그** — 먹물 변경 함수는 예외 없이 `users/{uid}/transactions`에 `{type, amount, reason, ts}` 기록
  ② **절대값 덮어쓰기 금지** — `meokmul: n`이 아니라 `FieldValue.increment(±n)`
  ③ **중복 결제 2단** — 클라이언트 lock(버튼 disabled + "처리 중") **와** 서버 멱등키(`crypto.randomUUID()`) 체크앤셋
  ④ **캐시 헤더 우선순위** — 자주 바뀌는 자산 규칙을 immutable 규칙 **뒤**에 배치
- 학습 통계 업로드는 **옵트인**, 개인 식별정보 미포함.

### 3-3. 개인정보 설계 (아동 서비스)

- 아이에게 **실명·생년월일·연락처를 묻지 않는다.** 닉네임은 **자동 생성**(자유 입력은 실명 입력 위험).
- 저장 기본값 = **기기 로컬**. 클라우드는 부모 연동 후 옵트인.
- 업로드 항목: `유형코드·정답여부·응답시간·타임스탬프`. 문항 원문·닉네임 미포함.
- 보유기간: 학습 통계 **12개월**, 이후 자동 파기. 국외 이전(Firebase 리전) 고지 문안 준비.
- 삭제 요청 시: **문서 삭제와 스토리지 객체 정리를 둘 다** 수행(문서 TTL이 객체까지 지운다고 가정하지 않는다).

### 3-5. 학습 효과 주장의 한계 (정직하게)

> 파일럿 8명·통제군 없음·20문항 사전사후로는 **"이 게임이 학습을 시켰다"고 주장할 수 없다.**
> 관찰된 향상은 연습 효과·검사 반복 효과와 구분되지 않는다.

- **v1에서 주장 가능한 것**: "아이가 이 게임에서 주당 N문항을 풀었고, 유형별 정확도·속도가 이렇게 변했다"(기록).
- **v1에서 주장하지 않는 것**: "학습 효과가 검증되었다"(효능).
- **효능 주장을 하려면**: 사전분석계획(선등록) + **미학습 유형 대조**(같은 아이 안에서 게임에 안 나온
  유형을 대조군으로) + 독립 검사지 + 표본 40명 이상. → **v2 별도 트랙**으로 분리하고 예산에 반영.

### 5-1. Headless 시뮬 (`tools/headless-sim.mjs`)

**시나리오 4종**: ① 표준(정답 85%) ② 풀 테크(95%·고코스트) ③ 일부러 지기(무응답·무소환) ④ 교착(420초)
**불변식(매 틱)**: 셈력 ≥0 · 성 HP ≤최대 · HP≤0 유닛 잔존 0 · 아군 ≤60기 · 콤보 배율 ∈{1.0,1.2,1.4,1.6} · SRS 상태 ∈5종 · DDA 단계 ∈0~3
**밸런스 회귀**: `balance-probe.mjs`를 CI에 넣어 게이트 G1·G1b·G2·G3·G4·G5·G7이 계속 통과하는지 확인.

### 5-2. 시각 QA — 하네스 함정 대비
- 프리뷰 포트 **전용 + `--strictPort`**, 시작 시 `document.title` 대조(엉뚱한 앱 검수 방지)
- Puppeteer `headless:'shell'` + CPU 래스터 플래그, QA 전용 `?qa=1`로 Canvas 렌더러
- QA 훅 전역 키 `window.__gugu__` (`window.game`은 DOM id에 점유될 수 있다)
- **셀렉터가 없으면 FAIL로 센다**(null이면 조용히 통과하는 사고 방지)
- 모달 검사는 `overflow-y:auto`에 속지 않게 **선택지가 뷰포트 안에 있는지 직접 측정**
