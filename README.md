|---|---|
| `CLOUDFLARE_API_TOKEN` | Cloudflare 대시보드 → My Profile → API Tokens → **Edit Cloudflare Workers** 템플릿(Pages 쓰기 포함) |

시크릿을 넣기 전까지는 배포 때마다 이걸 손으로 쳐야 합니다:

```bash
npm run build
npx wrangler pages deploy dist --project-name gugu-guardians --branch main
```

`dist/` 폴더를 정적 호스팅에 그대로 올리면 끝입니다(Netlify·Vercel·GitHub Pages·학교 서버 등).
게임 자체에는 API 키도 시크릿도 없습니다 — 번들에 들어가는 유일한 외부 주소는 순위 서버의 공개 URL입니다.

주간 순위를 안 쓰려면 `.env.production` 의 `VITE_BOARD_URL` 을 비우면 됩니다.
그러면 메뉴에 버튼조차 생기지 않고 네트워크 요청이 0건이 됩니다.

### 순위 서버 (선택)

```bash
npx wrangler login
npm run deploy:server     # server/ → Cloudflare Worker + Durable Object
```

배포되면 나오는 주소를 `.env.production` 의 `VITE_BOARD_URL` 에 적습니다.
D1 대신 **SQLite 기반 Durable Object** 를 씁니다 — 순위 갱신이 read-modify-write라
강한 일관성이 필요하고, D1 은 계정당 10개 상한이 있기 때문입니다.
규칙·상한·검증은 `shared/board-contract.ts` **한 파일**에 있고 앱과 워커가 같이 씁니다
(양쪽에 복붙하면 한쪽만 고쳤을 때 특정 별명을 뽑은 아이의 제출만 조용히 실패합니다).

### 파일 하나로 배포

```bash
npm run build:single   # dist-single/gugu-guardians.html (약 2.5MB)
```

그림·소리·코드를 전부 data URI로 넣은 **단일 HTML**입니다. 외부 요청 0건이라
더블클릭으로 바로 열리고(`file://` 검증 완료), 파일 하나만 올릴 수 있는 곳
(아티팩트·이메일·USB·엄격한 CSP 호스팅)에도 그대로 들어갑니다.
배경만 1024px로 재인코딩합니다 — base64가 원본의 약 1.33배로 부풀기 때문입니다.

> 🔴 이 빌드는 `--mode single`(`.env.single`)로 **주간 순위를 끈 채** 만들어집니다.
> 아티팩트는 CSP가 외부 요청을 전부 막으므로, 켜 두면 콘솔 에러만 남습니다.
> 빌더가 결과물에 외부 주소가 남았는지 기계로 검사하고 남아 있으면 빌드를 실패시킵니다.

## 무엇이 아이를 계속하게 하는가

| 층 | 내용 |
|---|---|
| **무한 스테이지** | 10판마다 새 구역(배경·적 구성·문항 유형이 바뀌고 10판째는 수문장). 1~30판은 **소환 없이** 깨지도록 보장하고, 31판부터는 무한 도전 |
| **5등급 셈지기 38종** | 노멀 · 레어 · 유니크 · 에픽 · 전설. 23종은 진도로 **공짜 해금**, 15종은 소환 전용 |
| **소환과 승급** | 먹물로 뽑고, 중복은 조각이 되어 승급(레벨당 +8%). 등급별 상한 5~15레벨 |
| **오늘의 임무** | 날마다 짧은 목표 3개(날짜에서 결정론 생성). 다 하면 먹물 덤. **못 해도 잃는 것은 없다** |
| **다음 합류 예고** | 다섯 판 안에 열릴 셈지기를 미리 알려 준다 — "한 판만 더"의 근거 |

> 🔴 **소환 재화(먹물)는 문제를 맞혀야만 나온다. 현금 결제는 없다.**
> 확률은 전부 공시하고(노멀 55% … 전설 1%), **10연에 유니크 이상 확정 · 60회 안에 전설 확정**.
> 운이 나쁜 아이가 영원히 못 뽑는 구조는 학습 보상으로 쓸 수 없다.

무한 구간에서 어디까지 가는지는 전력에 달려 있다 — 프로브 실측:
캠페인 로스터만 **ST50**, 유니크 확보 **ST55**, 전설 확보·승급 **ST60**.

## 어떻게 학습이 일어나는가

**3층 구조**이고, 각 층의 역할이 다릅니다.

| 층 | 위치 | 목적 |
|---|---|---|
| **L1 유창성** | 전투 중 하단 문제 | 이미 아는 것을 **빠르게**. 정답이 자원(셈력)의 주 공급원 |
| **L2 정확성** | 클리어 직후 '봉인 해제' 5문항 | 새 개념·오개념 교정. **별점을 여기서 결정** |
| **L3 파지** | 세션 간 SRS(1→3→7→21일) | 오래 기억하기 |

핵심 규칙 3가지:

1. **전투 중에는 새 개념을 가르치지 않는다.** 전투를 보면서 새로운 걸 배울 수는 없습니다. L1은 자동화 전용.
2. **오답은 처벌하지 않는다.** 성 HP를 깎지 않고, 콤보만 끊기며 힌트를 줍니다. 두 번 틀리면 정답을 알려주고 넘어갑니다.
3. **별은 게임 실력이 아니라 학습이 준다.** 전투를 이겨도 봉인 해제 문항을 못 풀면 별 1개입니다.

문제는 전부 **절차적으로 생성**합니다(문제은행 파일 없음). 교재를 옮겨 적지 않으므로 저작권 문제가 없습니다.

## 밸런스는 추측이 아니라 실측입니다

`tools/balance-probe.mjs` 가 **스테이지(16) × 정답률(6) × 시드(21) = 2,016판**을 실제로 굴려 게이트를 판정합니다.
무한 구간(31~60판)은 로스터 등급별로 따로 굴려 "소환이 실제로 더 멀리 가게 하는가"를 확인합니다.

| 게이트 | 뜻 | 실측 |
|---|---|---|
| G1 | 잘하는 아이의 한 판 길이 | 63~75초 |
| **G2** | **정답률 60%인 아이도 캠페인 30판을 전부 깰 수 있는가** (하드월 금지 — 가장 중요) | 최저 승률 86% |
| G3 | 문제를 안 풀면 막히는가 (학습 유인) | 정답 0%는 3판부터 못 깸 |
| G4 | 정답률이 높을수록 실제로 빨라지는가 (역전 금지) | 통과 |
| G5 | 한 판에 20문항 이상 푸는가 | 22~27문항 |
| G7 | 수문장(매 구역 10판째)도 저성취가 깰 수 있는가 | 60% 승률 100% |
| G8 | 잘하는 아이도 **자주 지는가** (긴장) · 어려워하는 아이는 낮은 단계에 머무는가 (안전망) | 정답40% 0.0단계 · 정답95% 49% 패배 |
| G9 | 못 깨던 판을 전력을 키워 깰 수 있는가 (재도전 루프) | 승률 +33~43%p |
| **G12** | **같은 정답률에서 빠르게 푸는 사람에게도 천장이 있는가** | 어른(1.0초/문항) 52% 패배 |

이 프로브가 기획 단계에서 실제로 잡아낸 설계 파탄:

- **적 종류를 3종 추가했더니** ST10 총 체력이 51% 뛰어 전 구간 전멸 → 수량을 적별 계수가 아니라
  **총 체력 예산의 지분**으로 배분하도록 변경(종류를 늘려도 총 난이도가 안 변한다)
- 덱 추천을 **등급 우선**으로 뒀더니 `짚신이(30) + 장승(520)` 같은 극단 덱이 나와 전멸 →
  역할 커버리지(물량·탱커·원거리·결정타·가성비)로 변경
- 진도 해금이 9판에서 끝나 **10~30판 내내 전력이 그대로**였음 → 15종을 30판에 고르게 폄
- 정답 보상이 고정이라 후반에 셈력 수입이 물량 증가를 못 따라감 → **보상을 물량 곡선에 연동**
- 적은 지수(1.16ⁿ)·아군은 선형(1.06ⁿ)으로 짜서 **ST6부터 전 실력 구간 전멸**
- **무한 스폰**이 "느릴수록 적이 쌓이는" 죽음의 나선을 만들어 저성취 아동을 막고 있었음 → 총 물량 고정
- 아군 성장에 필요한 재화가 **획득 가능량의 40배**(23,818 vs 540) → 성장을 진도 연동 자동으로 변경
- **4지선다(무작위 25%)로 스테이지 6개가 그냥 통과** → 주 입력을 숫자패드로 확정
- **실력을 정답률 하나로만 모델링해서, 빠르게 푸는 사람에게는 난이도 천장이 아예 없었다**(2026-08-20).
  프로브의 응답 시간이 `2.3 + (1-정답률)×2.4` 초라 **가장 빠른 플레이어조차 문항당 2.3초**였고,
  구구단을 1초에 답하는 어른·숙달 아동은 게이트가 한 번도 본 적이 없었다. 그래서 프로브는
  "정답 95% 아이 패배율 40%"라고 초록불을 켜는 동안 실사용자는 같은 빌드를 네 번 "너무 쉽다"고 보고했다.
  속도 축을 넣고 재니 **어른 패배율 3% · 성 피격률 6% · 최고 난이도에 못 박아도 승률 99%** 였다.
  → 난이도 천장을 12단계에서 20단계로 올리고, 승격 신호에 **응답 속도**를 더하고,
  상단은 공격력이 아니라 **물량**으로 밀도록 바꿨다(공격력만 올리면 성이 즉사해 '아슬아슬한 판'이 사라진다).
  결과: 어른 패배율 3% → **52%**, 성 피격률 6% → **48%**. 재발 방지로 **G12 속도 게이트**를 상설화했다.
- **승격 조건이 자기가 만든 난이도 때문에 스스로 닫혀 있었다.** 압도 판정이 정답률 0.9 고정이었는데
  단계가 오르면 문항이 어려워져 같은 아이의 정답률이 0.86으로 내려간다 → 3단계 위로는 영영 승격 불가.
  기준을 **그 단계의 목표 정답률 + 5%p**로 바꿨다(0단계는 0.90 그대로 = 안전망 불변).
- **높은 공격력이 '특기'로 취급되지 않았다.** 예산 지분은 총 **체력**만 고정하는데 `빼기까마귀`는
  공격력 72(잡몹 최고, 물음표벌레의 3배)로 지분 0.10을 받고 있었다 → 이 괴수가 사는 ST12~20 구간만
  뒤보다 어려운 **비단조 구간**이 생겼다(16단계에서 ST14 29% vs ST21 90%). 지분을 0.05로 내려 폈다.
- **수문장 판에 물량 배율이 이중으로 걸렸다.** 보스 판은 이미 예산의 125%(잡몹 75% + 보스 50%)를
  지는데 잡몹 쪽에만 배율이 곱해져 절벽이 됐다(16단계 ST10★ 38% vs 인접 판 76~86%) → 보스 판 전체를 배율에서 제외.

## 저작권 안전 설계

같은 장르(사이드뷰 라인 디펜스)는 2007년 *Age of War* 등으로 이미 널리 퍼진 형식입니다.
다만 **국내 판례상 "게임 규칙은 무조건 자유"는 틀린 단정**이라, 규칙 유사성에 기대지 않고 설계했습니다.

- 자원 파이프 자체를 **학습으로 치환**(다른 게임에 없는 구조)
- 아트를 **한국 민화·단청**으로 원천 분리, **고양이 캐릭터 전면 배제**
- 유닛·재화·적 명칭 전부 자체 창작
- 문항은 절차 생성(교재 복제 없음)
- 마케팅 문구에 경쟁작 이름을 쓰지 않음

상세와 남은 확인 항목: `docs/RESEARCH.md §3`

## 개인정보

- 로그인 없음. 이름·생년월일·연락처를 묻지 않습니다. 별명은 자동 생성됩니다.
- 학습 기록(문항 이력·정답률·θ·SRS)은 브라우저 `localStorage`에만 있고 **전송되지 않습니다.**
- 설정 화면에서 언제든 전부 지울 수 있습니다.

### 주간 순위를 켰을 때만 나가는 것

기본값은 **꺼짐**입니다. 켜기 전에는 요청이 한 건도 나가지 않고, 기기 표식조차 만들지 않습니다.
(`tools/e2e-board.mjs` 가 브라우저 네트워크를 관찰해 이걸 매번 실측합니다.)

켜면 나가는 값은 이게 전부입니다:

| 보내는 것 | 형태 |
|---|---|
| 별명 | 문자열이 아니라 **자동 생성 목록의 인덱스 두 개**(0~7) |
| 이번 주 맞힌 문제 수 / 가장 멀리 간 판 | 정수 |
| 이번 주 플레이 시간 | 정수(ms). **참고값**이라 서버가 자기 시계로 다시 상한을 씌웁니다 |
| 기기 표식 | 켜는 순간 만든 난수 UUID |

> 🔴 **API에 자유 문자열 필드가 없습니다.** 별명을 문자열로 받지 않기 때문에
> 아이가 실명·학교·연락처를 순위표에 올릴 경로가 **물리적으로 존재하지 않습니다.**
> 문자열을 받아 놓고 걸러내는 방식은 언제나 뚫립니다 — 애초에 받지 않는 게 유일하게 확실합니다.

서버는 IP·User-Agent를 저장하지 않습니다. 순위표에 뜨는 2글자 꼬리표는
`SHA-256(주 + 기기표식)`이라 되돌릴 수 없고 **매주 바뀝니다** — 고정이면 공개 순위표를
매주 긁어 특정 아이의 성적 추이를 따라갈 수 있기 때문입니다.

**"그만 올리기"를 누르면 서버에 올라간 기록도 그 자리에서 지웁니다**(`/forget`).
그대로 두는 기록은 어차피 8주 뒤 주 단위로 통째로 삭제됩니다.

> ⚠️ 다만 **"식별정보를 하나도 저장하지 않는다"고는 쓰지 않습니다.**
> 순위를 켜면 난수 UUID 하나가 최장 8주 저장되고, 그건 실명과 연결되지 않을 뿐
> **같은 기기를 주 단위로 알아보는 가명 식별자**입니다. 끄면 즉시 지워집니다.
> (순위를 켜지 않으면 이 UUID는 만들어지지도 않습니다.)
> 그리고 어떤 웹 호스팅이든 접속 로그는 남습니다 — 그건 우리 통제 밖입니다.

### 순위 조작에 대해 정직하게

처음 설계는 "정답 수 ÷ 플레이 시간"이 말이 되는지만 봤습니다. **분자도 분모도 클라이언트가
보내는 값**이라 시간을 일주일로 위조하면 정답 10만 개가 그대로 통과했고, 배포된 서버에서
실제로 재현됐습니다(교차검증 3개 계열이 전부 같은 곳을 짚었습니다).

지금은 분모가 **서버 자기 시계**입니다. 그 주에 서버가 이 기기를 처음 본 뒤로 실제로 흐른
시간까지만 인정하므로, 클라이언트가 뭐라고 보내든 시간을 앞당길 수 없습니다.
거절이 아니라 **깎습니다** — 늦게 동의한 아이가 에러만 보면 안 되고, 값은 누적이라
시간이 흐르면 자연히 따라잡습니다.

남는 한계도 적어 둡니다: 표시 상한(주당 정답 3,000 · 도달 300판)까지는 **오래 기다리면**
도달할 수 있습니다. 서버가 실제 플레이를 관찰할 방법이 없으니 계정 없이 이보다 더 막을 수는
없습니다. 대신 상한을 실측에 붙여 놨기 때문에(승리 한 판 9~61문항 · 실측 도달 한계 ST60),
조작해도 **아주 열심히 한 아이와 같은 자리**까지가 전부입니다. 상금이 걸린 랭킹이 아니라
교실용 동기부여 장치라 이 선이 맞다고 판단했습니다.
